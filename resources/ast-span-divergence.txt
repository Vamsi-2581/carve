# Node types the three engines SPAN differently.
#
# `npm run ast:check` compares every corpus document's AST across carve-js,
# carve-rs and carve-php. This ledger makes a newly introduced position presence
# or extent disagreement fail conformance instead of becoming an unnoticed
# baseline.
#
# Format, one row per diverging node type:
#
#   <type> (presence|extent)  <document-count>  <who diverges and where it is tracked>
#
# The declaration is exact in three directions, and `reconcileSpans`
# (scripts/spec/ast-spans.mjs) reports each one:
#
#   - a type diverges and is not listed     -> NEW, fails
#   - a listed type no longer diverges      -> AGREED, delete the row, fails
#                                              until you do
#   - a listed type's DOCUMENT COUNT moves  -> COUNT, the divergence spread or
#                                              shrank, fails
#
# The count is what keeps the second and third honest. A list of document names
# would churn on every corpus insertion; a count describes the same fact and
# still fails when the fact changes.
#
# A ROW KEY IS A TYPE, NOT A DEFECT. One key can carry faults owned by different
# issues in different engines, and no number here says so - so the third column
# names who diverges and where it is tracked, fully qualified as
# `owner/repo#NNNN`. That reference is what makes a short row safe to read;
# without it a row is a rumor, and `reconcileSpans` refuses a row that omits it.
#
# A row does not say WHICH engine is wrong: this panel has the trees and not the
# source. `npm run ast:check` prints the reasoning, and PART 12 §4 names the side
# only where `checkOpeningMarkup` / `checkStopsAtChildren` in
# scripts/spec/ast-positions.mjs can see it.
#
# HOW A MEASUREMENT IS RECORDED. In the pull request that took it, not here. This
# file states what is declared NOW; the run that established it, the engine
# commits it was taken at, and what moved since are the PR's job, where they are
# immutable and nobody has to scroll past them to reach the rows.
#
# BOTH ROWS, and why no engine owes either of them. Both are the same
# document, 503-...-at-every-depth-9, whose fourth line is a bullet indented
# under a nested definition term. carve-js and carve-rs open the `list` at the
# `-` marker; carve-php opens it at column 3, its parent description's content
# column, and the two columns differ only inside the line's leading
# indentation. `list` and `list_item` are both containers and both in
# `INDENT_LATITUDE`, so markup-carve/carve#1928 makes both readings conformant
# and neither engine has a row to answer for. The document arrived with
# markup-carve/carve#2426.
